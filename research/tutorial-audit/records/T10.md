## 如何讀取時間與品質

`Inference time` 來自驗證器的每張推論耗時，不包含前處理、後處理、匯出、檔案讀取及整個程序啟動。FPS 是 `1000 / (推論毫秒 + 0.001)`，不是攝影機應用的端到端 FPS。

benchmark 先做一次圖片預測，驗證器還會呼叫 backend 的 warmup；本次沿用這個流程，沒有額外加入長時間暖機或多次計時迴圈。只有 4 張驗證圖、兩輪固定順序，未控制電源模式、其他程序負載或統一兩種 runtime 的執行緒設定，因此不作正式性能排名。

PyTorch 首次完整子程序為 6.78 秒，ONNX 為 12.29 秒；包含 import、匯出（ONNX）、預測、驗證及保存表格。這些時間不能拿來代替每張推論時間。兩輪完整耗時見 [首次](T10-assets/logs/execution.json) 與 [重跑](T10-assets/logs/repeat-execution.json)。

品質只確認四捨五入至 4 位小數後相同，沒有保存未取整的完整 metrics，也不能由 COCO8 證明泛化品質。這次使用原始模型與方形、batch=1 的 Benchmark 設定，不能直接拿 T07 訓練模型的指標比較後判定退步。

## 教學順暢度、調整與未執行格式

指定格式的例子可直接使用，沒有新阻塞。與原文的差異是明確指定 CPU、使用模型絕對路徑、另外執行 PyTorch 基準及保存證據；GPU 全格式範例未執行。

需要理解的細節：

1. `format="onnx"` 只回傳 ONNX 一列，不自動附 PyTorch 基準。用表格列出的 `format="-"` 另跑即可，不需自行改函式。
2. 回傳值是 Polars DataFrame，欄位已轉為字串，失敗數值可能是 `"-"`。本次保存原表，不把空值或失敗值當成 0。
3. `benchmarks.log` 會追加到 cwd；驗證輸出則使用 runs_dir。因此腳本為各格式建立 cwd 和獨立設定副本，只修改副本的 runs_dir，不改動原本共用設定。
4. 未指定 format 會嘗試多種格式；本次設定 `YOLO_AUTOINSTALL=False` 並限定格式，以沿用現有依賴。未執行官方的整包 export extras 安裝。

| 未執行項目 | 原因／狀態 |
| --- | --- |
| TorchScript | 本輪限定 PyTorch／ONNX；未測，不代表不支援 |
| OpenVINO、其他一般匯出格式 | 本輪未擴充依賴與範圍；未測 |
| TensorRT／GPU | 此研究環境是 CPU；未測 |
| CoreML、行動／專用硬體格式 | 沒有建立對應平台與 runtime；未測 |

以上是本次主動排除，**不是 runtime 實際跳過或失敗的列**。所選兩種格式沒有跳過項目。ONNX 較慢的原因尚未隔離，不能直接判為產品 bug。
