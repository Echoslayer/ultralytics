#### 為什麼 T01 下載到工作目錄？

本次實測了前兩項查找規則；第三項下載行為採用 T01 已保留的首次下載證據，並對照目前安裝版本的函式原始碼：

1. 傳入路徑已有檔案，直接使用它；裸檔名相對於 cwd。
2. 否則檢查 `weights_dir / 傳入路徑` 是否已有檔案。
3. 兩處都沒有官方模型資產時，下載函式使用傳入的 `file` 作為目的地。裸檔名仍相對於 cwd。

因此 `weights_dir` 不會搬移現有檔案，也不是所有下載的強制目的地。需要明確位置時，先建立目錄，再傳入完整模型路徑。本次沒有重新下載或驗證缺檔完整路徑的網路行為，不把原始碼閱讀當作新的下載實測。

證據：[本次安裝套件的查找函式](T05-assets/logs/download-owner.py)、[解析路徑與框數](T05-assets/logs/results.json)、[T01 首次下載紀錄](T01.md)。本機 worktree 的同名函式也有相同查找與下載分支。

### T05-C：reset 是恢復預設，不是復原上一次修改

CLI 執行 `yolo settings reset`，新程序確認自訂 runs_dir 已清除。再由 Python 設定自訂值、呼叫 `settings.reset()`，確認不再使用自訂 runs_dir；另一新程序確認此結果持續有效。

Error：無。Warning：無。這次驗證 reset 的代表欄位是 runs_dir，沒有逐項比較全部預設值。不要把更新與 reset 當成必須連續執行的設定步驟；若照著範例兩者都執行，最後留下的是預設值。
