## T03-A：取得框的座標、類別與信心分數

官方範例的重點是 `result.boxes`。以下是這次使用的最小讀取方式；完整存檔與驗證程式在 [t03.py](T03-assets/logs/t03.py)。

```python
from ultralytics import YOLO

model = YOLO("yolo26n.pt")
results = model.predict(source="bus.jpg", device="cpu", conf=0.25)
result = results[0]
for xyxy, cls, conf in zip(result.boxes.xyxy, result.boxes.cls, result.boxes.conf):
    print(result.names[int(cls)], float(conf), xyxy.tolist())
```

`results` 是包含 1 個 Results 的清單，並不是 5 個物件的清單。5 個偵測框位於 `results[0].boxes`。

| 列號 | 類別編號／名稱 | 圖片位置 | 信心分數（顯示六位） | xyxy 像素座標（顯示一位） |
| --- | --- | --- | --- | --- |
| 0 | 5／bus | 公車 | 0.880600 | [0.0, 230.5, 803.2, 750.7] |
| 1 | 0／person | 左側主要行人 | 0.872011 | [48.6, 397.7, 240.3, 902.4] |
| 2 | 0／person | 中間行人 | 0.860808 | [222.9, 404.8, 345.5, 861.0] |
| 3 | 0／person | 右側邊緣行人 | 0.846248 | [669.6, 394.5, 809.9, 879.4] |
| 4 | 0／person | 最左側部分入鏡行人 | 0.656220 | [0.2, 553.0, 59.7, 871.3] |

列號只是這次結果的順序，不是追蹤 ID。類別編號用 `result.names` 查名稱，不要假設所有模型都用 0 表示行人。分數也不是模型在資料集上的準確率。

### 座標怎麼讀

圖片左上角是原點，x 向右、y 向下。`orig_shape` 是 **[高, 寬] = [1080, 810]**，不是寬在前。日誌中的 640 × 480 是模型處理尺寸；以下座標已對應回原圖。

| 欄位 | 本次形狀 | 意義 |
| --- | --- | --- |
| `boxes.xyxy` | [5, 4] | 左上 x、左上 y、右下 x、右下 y，單位是原圖像素 |
| `boxes.xywh` | [5, 4] | 中心 x、中心 y、寬、高；前兩欄不是左上角 |
| `boxes.xyxyn` | [5, 4] | xyxy 的 x 除以圖寬，y 除以圖高 |
| `boxes.xywhn` | [5, 4] | xywh 的 x／寬除以圖寬，y／高除以圖高 |
| `boxes.cls`、`boxes.conf` | 各 [5] | 類別編號、信心分數 |
| `boxes.data` | [5, 6] | 本次非追蹤偵測資料：x1、y1、x2、y2、conf、cls |

例如公車的中心約為 (401.6, 490.6)，寬高約為 (803.2, 520.2)。中心正規化後約為 (0.495800, 0.454249)。完整數字見 [results.json](T03-assets/logs/results.json)。

[bus.txt](T03-assets/output/bus.txt) 每列則是 `cls 中心x 中心y 寬 高 conf`，座標已正規化。它與 `boxes.data` 都有六欄，但順序和座標格式不同。

## T03-B：確認跨任務欄位的教學卡點

本機官方文件 `Predict / Results usage` 同一區塊列出偵測、分割和分類欄位。區塊已有任務註解，但初學者若把所有行接著執行，可能誤以為每個 Results 都有這些資料。

我們在主流程成功後，另用 [探測腳本](T03-assets/logs/t03-masks-probe.py) 執行同一張圖，再刻意讀取 `result.masks.data`。這不是主流程的首次失敗，也不是逐字執行整段官方範例。

| 項目 | 實際結果 |
| --- | --- |
| 輸入 | 同一個偵測模型與公車圖片 |
| 先前觀察 | `result.masks is None`，`result.probs is None` |
| 出錯位置 | 探測腳本第 5 行，`result.masks.data` |
| 錯誤 | `AttributeError: 'NoneType' object has no attribute 'data'` |
| 退出碼 | 1；該程序在讀取欄位時停止，預測本身已完成 |
| 證據 | [完整錯誤日誌](T03-assets/logs/masks-probe.log) |

這次模型用來偵測物件，不產生分割遮罩或整張圖的分類機率。固定做偵測時，只取 `boxes`；若程式真的要支援多任務，再依結果是否為 None 選擇欄位。不要用捕捉例外來掩蓋任務不符。

PowerShell 在錯誤日誌加上 `NativeCommandError` 和位置資訊；真正的 Python 錯誤是最後一行 AttributeError。這次退出碼確實為 1，不是只有 shell 把標準錯誤輸出顯示成紅字。

## 本機重跑方式

先確認 T01 的 Temp 環境、模型和圖片仍存在。以下每次建立新輸出位置，避免混入舊結果；腳本遇到既有目錄也會拒絕覆寫。

```powershell
$repo = 'D:\tools\ultralytics\.worktrees\contribution-research'
$runRoot = 'C:\Users\edisonhsieh\AppData\Local\Temp\ultralytics-tutorial-0d928fdb911d405f850a79ca00613d55'
$env:YOLO_CONFIG_DIR = Join-Path $runRoot 'config'
$env:UV_CACHE_DIR = Join-Path $env:TEMP 'ultralytics-validation-uv-cache'
$python = Join-Path $runRoot '.venv\Scripts\python.exe'
$script = Join-Path $repo 'research\tutorial-audit\records\T03-assets\logs\t03.py'
$output = Join-Path $runRoot ('t03-' + [guid]::NewGuid().ToString('N'))
Set-Location $runRoot
& $python $script $output
$LASTEXITCODE
Get-ChildItem $output
```

預期退出碼為 0，輸出包含 `bus.jpg`、`bus.txt`、`results.json`。若 Temp 已清除，先按 [T01](T01.md) 重建環境和資產。錯誤探測可另外執行同目錄的 `t03-masks-probe.py`；預期退出碼為 1。
