## 候選 1：mask 轉換的「binary」說法

[`simple-utilities.md`](https://github.com/ultralytics/ultralytics/blob/main/docs/en/usage/simple-utilities.md) 寫 “takes the directory containing the binary format mask images”。實際上像素值是類別索引 + 1，0 是背景：

| 輸入 mask | `classes=80` 的輸出 |
| --- | --- |
| 同時含像素值 1 與 255 | 只有 1 對應到 class 0；255 顯示 `Unknown class` 警告並跳過 |
| 只含 0 與 255 | 空的 `.txt`，只有一條警告 |

- [`datasets/segment/index.md`](https://github.com/ultralytics/ultralytics/blob/main/docs/en/datasets/segment/index.md) 與函式的 docstring 都已寫對，只剩這一頁。
- [#15098](https://github.com/ultralytics/ultralytics/issues/15098) 的使用者就是拿 0/255 的道路 mask 碰到這個問題。
- 2026-10-30 搜尋 open PR，沒有人處理。

修法是一句話，沿用另外兩處的措辭。2026-10-31 已在 main `58876de55`（8.4.194）改好並驗證，送出 [PR #26971](https://github.com/ultralytics/ultralytics/pull/26971)；提案與 PR 草稿見 [proposals/mask-converter-docs](../../../proposals/mask-converter-docs/README.md)。

```markdown
This function takes the directory containing grayscale mask images, where each pixel value is the class index + 1 and 0
is background, and converts them into YOLO segmentation format.
```

## 候選 2：predict 的 `.txt` 來源與 `batch`

`LoadImagesAndVideos` 支援 `.txt` 與 `.csv` 清單，但來源表只有 CSV。`batch` 的說明卻把讀者連到這張表，並寫「directory, video file, or `.txt` file」。實測 `batch=2`、3 張圖（[`src.log`](T14-assets/src.log)）：

| 來源 | 載入器 | 批次 |
| --- | --- | --- |
| `.txt`、`.csv`、glob、目錄 | `LoadImagesAndVideos` | `[2, 1]` |
| 路徑 list | `LoadPilAndNumpy` | `[3]`，`batch` 被忽略 |

清單中的相對路徑會先對 cwd 解析，找不到再對清單檔解析。

修法：來源表把 CSV 列擴成 TXT／CSV，`batch` 的說明補上 `.csv` 與 glob。這項比候選 1 弱，沒有使用者回報，維護者也可能認為不值得改。2026-10-31 決定暫緩、不與候選 1 合併，等候選 1 的審查結果再看。路徑 list 忽略 `batch` 表示大量路徑會一次進模型，可能有記憶體風險，但這次沒有測大量圖片，也沒查過是否為刻意設計，留作待查。

## 本輪的教訓

- **機械比對抓不到行為說明的錯。** import、參數、連結都乾淨，再用這類方法找不到東西。
- **同一件事寫在多頁時，比對各頁的措辭。** 候選 1 的正確版本就在另一頁。
- **逐塊隔離執行只適合獨立範例。** 教學式頁面要把同頁區塊接起來跑。
- **檢查工具也要驗證：** 先看它涵蓋了多少，再相信「全部通過」。
