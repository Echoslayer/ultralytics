# 探針實測：用本機測試找近期改動的缺陷

探針是只在本機跑的小測試，用來確認近期合併的改動有沒有缺陷。探針本身不送上游；找到缺陷時，送最小的修正，只有高風險回歸路徑才附一個測試。原因見研究書第一章「不要送只補測試的 PR」。

## 每一輪的步驟

1. **挑對象。** 從最近 2～4 週合併、改到 `ultralytics/` 的 PR 中，挑使用者常走的路徑。新程式最可能有缺陷，維護者也還記得脈絡。
2. **讀 diff 與 PR 討論，列出假設。** 每個假設寫成「在什麼輸入下，預期什麼，可能出錯在哪」。
3. **刪掉已討論的假設。** 讀 PR 正文與留言；作者或維護者已提到並接受的行為，不再探。R01 的 P1 就是在跑完後才發現已討論過。
4. **寫探針並在最新 main 跑。** 每個探針只印出觀察，不在第一次就寫 assert；先確認預期本身沒寫錯。R01 的 P2 一開始誤把 `len()` 當成幀數。
5. **查重後才動手修。** 搜尋相同症狀的 issue 與 PR。根因與修法明確就直接送修正 PR；預期行為不明或有多種修法時先開 issue。
