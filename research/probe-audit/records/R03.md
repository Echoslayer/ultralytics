# R03：任務文件的 Results 表格，換成 ONNX 再驗一次

日期：2026-10-30。基準：官方 main `ae2857e3e`（8.4.193）。環境同 [R01](R01.md)，onnxruntime 1.31.1。腳本：[`probe_r3.py`](R03-assets/probe_r3.py)；日誌：[`r3.log`](R03-assets/r3.log)（已刪除下載進度列）。

**結論：文件的說法全部與實際一致，沒有可送出的貢獻。**

## 對象

照 [R02](R02.md) 的建議，起點從近期 PR 換成文件範例。`docs/en/tasks/` 的五個任務頁各有一張 Results 表格，列出欄位的型別與形狀；obb 與 pose 頁另有可以直接驗證的說法。每一項都在 `.pt` 與匯出的 ONNX 上各跑一次（`imgsz=320`，classify 用 224）。

## 結果

| 探針 | 文件說法 | 觀察 | 判斷 |
| --- | --- | --- | --- |
| P1 | 五個任務頁表格的型別與形狀（共 21 個欄位） | `.pt` 與 ONNX 全部相符，例如 `masks.data` 為 `torch.uint8 (N,H,W)`、`obb.data` 為 `(N,7)`、`probs.top5` 為 5 個 `int` | 一致 |
| P2 | `obb.md`：`xyxyxyxy2xywhr(result.obb.xyxyxyxy)` 會得到 `w >= h`、角度在 `[-π/4, 3π/4)`，且仍是同一個矩形 | 原始預測中有 36 個（`.pt`）與 35 個（ONNX）框的 `w < h`；轉換後兩者都是 0 個，角度都在範圍內，轉回角點後差異為 0 | 一致 |
| P3 | `pose.md`：索引 0～16 依序為 Nose…Right Ankle | `coco-pose.yaml`、`.pt` 與 ONNX 的 metadata 都帶有相同的 `kpt_names`，順序與文件相同 | 一致 |

## 刪掉的假設

`.pt` 推論得到的 `masks.data` 為 `(5, 320, 256)`，ONNX 為 `(5, 320, 320)`，兩者都不是原圖的 1080×810。表格只寫 `(N,H,W)`，一開始看起來像文件缺口。但 [`docs/macros/predict-args.md`](https://github.com/ultralytics/ultralytics/blob/main/docs/macros/predict-args.md) 的 `retina_masks` 已經寫明：沒有啟用時，遮罩的大小就是推論時的影像大小。`.pt` 與 ONNX 的差異來自 `.pt` 用了 rect 填充，ONNX 則是固定輸入。這已有文件說明，不送。

## 本輪的教訓

- 「看起來像缺口」的說法，先搜尋 `docs/macros/` 再下判斷。參數說明集中在 macro 檔，不在任務頁。
- P2 比對角點時，x 與 y 各自排序，是寬鬆的「同一組點」檢查。差異為 0，結論成立；若有差異，要改成逐點配對。
- 三輪都沒有找到可送出的缺陷。本輪驗的是文件已明寫的說法，命中率低是預期的。下一輪可以把探針換到文件較少涵蓋的組合：`track` 搭配 OBB 或 pose、`batch>1` 的串流來源、`half=True` 的 ONNX，或 `val` 時用 ONNX 搭配 `rect`。
