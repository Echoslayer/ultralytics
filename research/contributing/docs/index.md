# Ultralytics 開源貢獻研究手冊

這本書回答一個實際問題：**如何從「想參與 Ultralytics」走到一筆值得維護者審查的小型貢獻？** 研究日期為 2026-10-28；它是可更新的研究快照，不是已認領的 issue 清單。

建議先建立可重現問題的能力，再選擇小型修正。首次貢獻的官方規範偏好範圍小的 bug、效能或文件改善；功能提案應先在 issue 取得維護者明確同意。這使「先做大型新模型或泛用重構」成為成本較高的起點。[官方貢獻規範](https://github.com/ultralytics/ultralytics/blob/main/CONTRIBUTING.md)

## 第一輪研究的判斷

本書建議以「既有行為的可驗證修正」為主線。CPU 資料轉換或文件與實作不一致，通常較容易準備公開輸入；匯出、效能與硬體問題有價值，但需要相符設備及量測契約。這是依據本機可執行性與審查成本的研究判斷，並非維護者已核准的工作排程。

不要把 issue 標籤當成根因：`bug` 仍可能是依賴或資料問題，`enhancement` 也不等於已批准新 API。每題至少要走過「重新查狀態 → 公開輸入重現 → 找到 owner → 明確預期 → 決定是否修正」。官方也把最小可重現範例列為回報核心。[MRE 指南](https://docs.ultralytics.com/help/minimum-reproducible-example/)

## 本輪交付界線

已建立獨立研究分支與書籍來源、查閱官方規範與公開案例。沒有替你留言、認領 issue、簽署 CLA 或開 PR，也沒有把案例中的效能數字當成本機測量結果。未來真正修復時，應另開以官方基準建立的工作分支。
