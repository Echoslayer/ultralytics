# 7. 貢獻集中在哪些人、領域與修改規模？

**Ultralytics 的合併成果集中於少數高產作者，但小量參與也很常見。外部作者的入口不限於文件，資料處理與既有套件修正同樣有實際成果。**

本章沿用 2026 年第三季的 **1,247 筆 PR（合併請求）**，其中 **992 筆已合併**。這次透過 GitHub API（讀取公開資料的程式介面）補取完整檔案清單與增刪行數，共 7,015 筆檔案變更紀錄。資料查核日期為 **2026-10-28**。

先看三個重點：

- 排除自動化與無法辨識的帳號後，86 位作者有 PR 獲合併。前 5 位作者占人工合併成果的 **70.1%**，也有 51 位作者各合併一筆。
- 已合併 PR 的中位數是 **2 個檔案、16 行增刪**。1–50 行的 PR 占已合併成果 **76.7%**。
- 外部作者只改套件程式的提案有 **189／235** 合併；純文件有 **54／63**。兩種範圍都有人成功，不必把第一次貢獻限制在改錯字。

以上數字來自[可重算的分布摘要](assets/pr-distribution-2026-q3.json)。它們描述這一季的樣本，不是個人投稿的成功機率，也不能直接衡量工作時數、技術難度或產品價值。

本節按實際檔案路徑分類，不用標題猜測功能。一筆 PR 可同時涉及多個領域，所以各列不能相加。

| 文件樹與說明檔          | 502        | 405      | 40.8%             |
| 測試 `tests/`           | 248        | 177      | 17.8%             |
| 自動流程與容器          | 112        | 86       | 8.7%              |
| 其他專案檔案            | 76         | 42       | 4.2%              |
| 範例實作                | 33         | 20       | 2.0%              |

來源：[分布摘要的 `touched_areas`](assets/pr-distribution-2026-q3.json)。此表包含自動化 PR。

「文件樹與說明檔」包括 `docs/`、任何位置的 `.md`／`.rst` 與根目錄 `mkdocs.yml`。因此，範例資料夾的 README 算文件；文件建置工具也算文件樹，不代表其中每個檔案都是文章。「自動流程與容器」指 `.github/` 與 `docker/`；其他根目錄設定歸其他專案檔案。

文件與測試可能是程式修改的配套。不能將 405 筆涉及文件的合併 PR 全部稱為「純文件貢獻」。真正只改文件類檔案的是 **224 筆**，占合併成果 **22.6%**。

## 修改規模：多數合併成果很小，但行數不等於驗證成本

本章的規模是 **新增行數＋刪除行數**，包括文件、測試與設定。它不是淨新增行數，也不是官方「非文件程式碼」審查門檻的計算方式。

| 增刪行數       | 全部提案 | 已合併 | 占合併成果 |
| -------------- | -------- | ------ | ---------- |
| 1–50           | 924      | 761    | 76.7%      |
| 51–200         | 195      | 153    | 15.4%      |
| 201–1,000      | 100      | 63     | 6.4%       |
| 1,001 以上     | 27       | 14     | 1.4%       |
| 查核時差異為 0 | 1        | 1      | 0.1%       |

全部提案的中位數是 **2 個檔案、17 行增刪**；已合併者是 **2 個檔案、16 行增刪**。來源：[分布摘要的 `size_groups`](assets/pr-distribution-2026-q3.json)。

差異為 0 的是 [#25816](https://github.com/ultralytics/ultralytics/pull/25816)。API 顯示它已合併，但此次查到的檔案清單與行數為零。本書單獨保留這筆，不把它當成「零工作就能合併」的案例，也未還原它最初的差異。

## 外部作者：小範圍程式修正與文件都值得考慮

此處沿用第五章的 109 位可辨識外部作者，共 **482 筆提案、359 筆合併**。分類依公開關係，不代表查證過的員工身分；包括本季新人與先前已有紀錄的人。

先按修改規模比較：

| 增刪行數   | 外部提案 | 已合併 | 截至查核時合併率 |
| ---------- | -------- | ------ | ---------------- |
| 1–50       | 383      | 311    | 81.2%            |
| 51–200     | 59       | 40     | 67.8%            |
| 201–1,000  | 28       | 4      | 14.3%            |
| 1,001 以上 | 11       | 3      | 27.3%            |

另有前述差異為 0 的 1 筆已合併 PR。大規模組的樣本少，尤其 1,001 行以上只有 11 筆，不能將這些比例當成穩定規律。

再按互不重疊的修改範圍比較：

| 範圍                 | 外部提案 | 已合併 | 合併率 |
| -------------------- | -------- | ------ | ------ |
| 只改套件程式         | 235      | 189    | 80.4%  |
| 只改文件類檔案       | 63       | 54     | 85.7%  |
| 跨兩種以上領域       | 174      | 113    | 64.9%  |
| 其餘單一領域或零差異 | 10       | 3      | 30.0%  |

來源：[分布摘要的 `external_size_groups` 與 `external_scopes`](assets/pr-distribution-2026-q3.json)。最後一列混合了極小樣本，不適合用來判斷哪些領域值得做。

**本書判斷：** 先從能完整驗證的小改動開始，有實際資料支持。但不能反過來說「把修改切到 50 行內就一定比較容易合併」。大改動可能本來就是較難的新功能；目前差異也可能是審查後已縮小的結果。跨領域修改有時是正確配套，例如程式修正同時更新測試與文件，不能為了表格中的合併率而拆掉必要部分。

| 你能取得的驗證條件         | 建議優先看                       | 第一份成果                           |

## 如何重算與理解分類限制？

- [完整 PR 檔案資料](assets/pr-files-2026-q3.json)記錄修改行數、檔案路徑與查核時的版本編號。
- [分布摘要](assets/pr-distribution-2026-q3.json)包含作者集中度、規模、互斥範圍及可重疊領域分類。
- [原 PR 資料](assets/pr-cohort-2026-q3.json)提供本季樣本與合併結果，仍沿用前一輪查核狀態。

程式沿用 `research/contributing/analysis/pr_outcomes.py`，沒有另建分析工具。執行既有命令即可離線重算；`--details` 會連到 GitHub，補取尚未保存的檔案資料，支援每筆超過 100 個檔案時繼續分頁。本輪最大的 PR 有 354 個檔案，並已核對 1,247 筆的檔案數與 API 回傳數一致。

```powershell
python research/contributing/analysis/pr_outcomes.py
python research/contributing/analysis/pr_outcomes.py --details
```

檔案資料擷取時間是 **2026-10-28 05:58:07–06:00:47 UTC**。本輪新取得的合併時間與先前 1,247 筆紀錄一致。`--details` 會保留已下載紀錄，不會自動刷新它們；若要另做新時間點研究，先保存這份資料，再安排新的資料版本。

分類是固定路徑規則，不是逐筆判斷功能價值。文件規則優先，其次是套件、測試、範例、自動流程與其他檔案；重新命名以此次 API 提供的路徑分類。本輪沒有還原最初提交規模、逐筆拆分作者與機器人產生的行數，也沒有衡量審查時間、工作量或功能重要性。
