# 9. 外部 PR 多久有回應？沒合併的原因是什麼？

**外部 PR 通常在一天內就有維護者回應；沒合併的 PR 中，最常見的原因是作者自己撤回、範圍或設計不符，以及已有別的修正。** 另有 14 筆雖然顯示「關閉」，修改其實已由維護者併入另一個 PR，並保留作者署名。

本章的「回應」指維護者留言、正式審查，或維護者直接合併、關閉。資料是 2026 年第三季外部作者提出的 **482 筆 PR**，查核日為 2026-10-29。外部作者的定義與[第五章](merge-rates.md)相同。

## 多久會有人回應？

| 結果              | PR 數 | 有維護者回應 | 中位數（小時） | P75（小時） | P90（小時） | 24 小時內 | 72 小時內 |
| ----------------- | ----: | -----------: | -------------: | ----------: | ----------: | --------: | --------: |
| 全部外部 PR       |   482 |          460 |           8.09 |       15.90 |       27.86 |       403 |       440 |
| 已合併            |   359 |          359 |           7.75 |       14.35 |       27.10 |       314 |       345 |
| 未合併（含開啟中） |   123 |          101 |          10.41 |       20.26 |       27.94 |        89 |        95 |

- 482 筆中，**403 筆（83.6%）在 24 小時內**得到回應，440 筆（91.3%）在 72 小時內。
- 有 22 筆從未得到維護者回應：20 筆是作者自己先關閉，2 筆仍開啟。
- 已合併的 359 筆中，有 99 筆沒有任何維護者留言或審查，是維護者直接合併。所以「合併」本身也算回應；只看留言會低估回應速度。
- 自動化帳號 `UltralyticsAssistant` 的歡迎與自動審查不計入。P75／P90 表示 75%／90% 的回應不超過該時間，以線性插值計算。

這表示：如果 PR 送出後兩、三天都沒有人回應，已經比 90% 的外部 PR 慢。這時先檢查 CI（自動測試）、CLA（貢獻者授權協議）與 PR 描述是否完整，再考慮留言詢問。

## 修改越小，合併越快

同一批外部 PR 依增刪行數與修改範圍分組。時間是「建立到合併」，只計入已合併者。

| 增刪行數 | 提出 | 已合併 | 合併中位數（小時） |
| -------- | ---: | -----: | -----------------: |
| 1–50     |  383 |    311 |              13.86 |
| 51–200   |   59 |     40 |              18.37 |
| 201–1000 |   28 |      4 |              27.79 |
| 1001 以上 |   11 |      3 |               1.93 |

| 只改哪一類檔案 | 提出 | 已合併 | 合併中位數（小時） |
| -------------- | ---: | -----: | -----------------: |
| 只改文件       |   63 |     54 |               6.24 |
| 只改套件程式   |  235 |    189 |              14.40 |
| 跨多種檔案     |  174 |    113 |              16.38 |
| 只改測試       |    3 |      0 |                  — |

- 超過 200 行的外部 PR，39 筆只合併 7 筆。1001 行以上的 1.93 小時只來自 3 筆，不能代表大型 PR 會更快。
- 只改測試的 3 筆都沒合併，與下一節「不收只加測試的 PR」一致。
- 行數與分類沿用[第七章](contribution-distribution.md)的定義；另有 1 筆空修改未列出。

## 116 筆關閉未合併：原因分類

逐筆讀關閉前後的維護者與作者留言，每筆只標一個主要原因。

| 主要原因                         | 筆數 | 常見說法                                                       |
| -------------------------------- | ---: | -------------------------------------------------------------- |
| 作者自行撤回                     |   26 | 拆成小 PR 重送、改走文件、內部用途、發現不適合                 |
| 範圍或設計不符                   |   24 | 太大、混入無關修改、只加測試、不在路線圖、收益不足以增加維護成本 |
| 重複、被取代或程式已移除         |   21 | 已有較早的同題 PR、主線已修好、修改的檔案已刪除                 |
| 沒有實際會觸發的錯誤             |   16 | 只有直接呼叫內部函式才會壞、沒有支援的使用路徑會走到           |
| 併入維護者的 PR，保留作者署名     |   14 | 同一作者的多個小修正合成一個 PR 一起合併                       |

| 沒有說明原因                     |    4 | 直接關閉                                                       |

## 從這些案例學到什麼？

1. **先證明使用者真的會遇到。** 「沒有實際會觸發的錯誤」16 筆中，11 筆來自同一位作者。他在 7 分鐘內送出 14 個 PR，維護者明確拒絕「以靜態掃描找邊界情況、大量送出 AI 輔助修改」。只修「理論上會壞」的程式，很少被接受。
2. **先搜尋同題 PR。** 21 筆是重複或已被取代。送出前搜尋議題號碼、錯誤字串與函式名稱。
3. **一個 PR 只做一件事。** 混入格式化、無關修正或新抽象層，常被要求拆開或直接關閉。
4. **被關閉不等於白做。** 14 筆的修改已以作者署名合併；多筆關閉留言也明說「歡迎更小的新 PR」。只看合併率會低估這些貢獻。
5. **先簽 CLA。** 有一筆修正正確，但三次提醒後仍未簽，因此被關閉。

## 與十二個月耗時研究的關係

研究分支的 `research/pr-merge-time/README.md`（不在本書網站內）另外研究 2025-10 至 2026-09 的 2,832 筆 PR，外部作者已合併者的中位數是 16.09 小時。本章只看第三季，外部已合併者的中位數是 14.13 小時。兩者研究期間不同，外部作者的分組方式也不同：那份研究依查核時的帳號關係分組，本書則依作者在季度開始前的紀錄分組。因此兩個數字不能直接相減。

## 資料與判讀限制

- 首次回應只看主討論串留言與正式審查的第一頁，加上合併或關閉事件。沒有計入逐行留言單獨出現、但沒有審查摘要的情況；也沒有計入外部平台或私訊。
- 「維護者」依留言當下顯示的 `MEMBER`、`OWNER`、`COLLABORATOR` 判定；排除作者本人與已知的自動化帳號。
- 關閉原因由本書人工判讀，每筆只取一個主要原因。不同人可能把同一筆歸入相鄰類別，例如「範圍不符」與「技術上有錯」。
- 只有 3 筆只改測試、11 筆超過 1000 行，小樣本的中位數只能當參考。
- 沒有控制修改內容、品質或事前溝通，以上都是描述，不是因果結論。
