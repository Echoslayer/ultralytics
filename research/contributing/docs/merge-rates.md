# 5. 有貢獻紀錄的人，PR 比較容易合併嗎？

**這次樣本中，有先前合併紀錄的外部作者，合併率較高、合併也較快；但新人並非沒有機會。** 每人只看本季第一筆 PR，有先前合併紀錄者為 **11／14（78.6%）**，首次在此專案提出 PR 者為 **51／88（58.0%）**。

這是觀察到的關係，不能據此認定差距全由身分造成。修改內容、品質、範圍、事前協調與作者經驗，都可能影響結果。這次沒有逐筆控制這些因素；有經驗組也只有 14 人。

資料查核日期為 **2026-10-28**。本章的「合併」指 PR（合併請求）合併；一般 issue（問題或提案）只有開啟、關閉等狀態，不會直接合併。議題關閉也不一定表示修正已合併。[GitHub PR 說明](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests)

## 先看對你最有用的比較：每位外部作者只取一筆

下表每人只取 **2026 年第三季最早建立的一筆 PR**。對新人來說，這就是其在本專案的第一筆；對有經驗者，則只是本季第一筆。這能避免一個人連續提出上百筆 PR，主導整組結果。

作者是否有經驗，以 **2026-07-01 以前**的紀錄判定，不使用成功合併後才可能取得的身分標籤。

| 7 月 1 日以前的紀錄     | 人數／PR 數 | 已合併 | 已關閉未合併 | 仍開啟 | 截至查核日合併率 | 14 天內合併率 | 已合併者的耗時中位數 |
| ----------------------- | ----------- | ------ | ------------ | ------ | ---------------- | ------------- | -------------------- |
| 本專案沒有先前 PR       | 88          | 51     | 34           | 3      | 58.0%            | 47／88＝53.4% | 17.22 小時           |
| 提過 PR，但尚無合併紀錄 | 7           | 5      | 2            | 0      | 71.4%            | 5／7＝71.4%   | 26.91 小時           |
| 至少一筆 PR 已合併      | 14          | 11     | 2            | 1      | 78.6%            | 11／14＝78.6% | 4.39 小時            |

來源：本輪以 GitHub 公開資料重算的[統計摘要](assets/pr-summary-2026-q3.json)，其中 `first_pr_per_external_author` 對應此表。

**怎麼讀：** 新人與已有合併紀錄者相差約 20.6 個百分點。這個樣本支持「值得累積可信的貢獻紀錄」，不支持「你第一次投稿就有固定 58% 成功機率」。表中的時間也只計算成功合併的 PR，不能當成所有人需要等多久，或第一次收到回覆的時間。

「外部」在此只指查核時未標為組織成員、專案協作者或自動化帳號的人，不是經過查證的僱用關係。本輪沒有以姓名、國籍或帳號名稱推斷員工身分。

## 為什麼不能直接把 NONE 當新人？

GitHub 的 `author_association` 是作者與專案的關係欄位。例如，`MEMBER` 代表組織成員，`CONTRIBUTOR` 代表曾向專案提交程式碼，`NONE` 代表沒有上述關聯。這些值不等於「員工」「資深工程師」或「第一次提出 PR」。[GitHub 欄位定義](https://docs.github.com/en/graphql/reference/issues#commentauthorassociation)

本輪找到的 88 位本季新人中，**55 位在查核時已標為 `CONTRIBUTOR`**。如果只把現在的 `NONE` 當新人，會把部分成功者移到另一組，再錯把剩下的低合併率當成新人的處境。

因此，本輪另查每位外部作者在 7 月 1 日以前的 PR 數與已合併數。這裡的「新人」只表示首次向 **Ultralytics 這個專案**提出 PR，不表示沒有其他開源經驗。

## 整季全部 PR 的結果如何？

- **992 筆已合併，合併率 79.6%。**
- **243 筆已關閉但未合併。** 可能包含撤回、重複或被其他方案取代，不能全部稱為審查拒絕。
- **12 筆仍開啟。** 它們還可能改變結果。

新人組的全部 PR 合併率為 72.1%，但每人等權後是 57.0%。這表示高產作者與多次投稿會明顯影響整體數字。不能只用整體高合併率推論每位新人的情況。

## 官方規範如何看待貢獻者經驗？

官方 `CONTRIBUTING.md` 明確表示，有可靠貢獻紀錄的人通常獲得較高審查優先順序。它沒有設定固定次數門檻；其他知名開源專案的良好紀錄，也可能受到考慮。首次貢獻則偏好小範圍修正。[官方貢獻規範](https://github.com/ultralytics/ultralytics/blob/main/CONTRIBUTING.md)

這說明經驗確實是官方公開承認的考量。但規範中的「可靠貢獻者」，不等於 API 裡所有 `CONTRIBUTOR`，也不等於本研究「曾合併一筆」的統計分類。這些分類只能幫助比較，不能取代維護者的實際判斷。

## 資料怎麼取得，如何重算？

1. 用 GitHub REST API，按建立時間由新到舊讀取全部狀態，每頁 100 筆。
2. 共讀 17 頁，直到最舊日期跨過 2026-07-01，再保留第三季建立的 PR。最後一頁最舊日期為 2026-06-27。
3. 用 GitHub 搜尋獨立核對：相同日期查詢回傳 **1,247 筆**，`incomplete_results=false`，與分頁結果一致。沒有使用搜尋 API 的前 1,000 筆當作完整資料。
4. 對 109 位可辨識的外部作者，透過 GraphQL 查詢 7 月 1 日前的 PR 數與合併數。將組織成員、協作者、自動化帳號及 `ghost` 排除在外部經驗比較之外。
5. 保留每筆 PR 的連結、作者、建立與合併時間、目前狀態、標籤及目標分支。用斷言檢查重複編號、日期範圍、合併時間與各組總和。

PR 資料擷取時間為 **2026-10-28 05:41:11–05:41:45 UTC**；作者歷史的查核時間另存於資料檔。分頁期間狀態仍可能變動，這不是單一時間點的資料庫交易快照。

## 這些數字不能回答什麼？

- **不能證明身分造成合併差異。** 本輪未控制修改大小、文件或程式類型、品質、草稿時間、審查者與事前協調。
- **不能推算僱用關係。** 組織成員不一定是員工；未標為成員的人也不保證不是員工。身分採查核時的公開值，未還原歷史組織權限。
- **不能把合併耗時當回覆速度。** 這裡從 PR 建立算到合併，包括草稿期間；未分析第一次人工回覆。
- **不能把第三季當永久規律。** 研究只涵蓋 92 天內建立的 PR；截至查核仍有未結案件，沒有排除草稿，也沒有按目標分支篩選。
- **不能忽略資料缺口。** 已刪除或搜尋無法取得的歷史 PR、帳號變更及索引差異，可能影響「首次」判定。`ghost` 無法還原成真實作者，因此未納入經驗比較。
- **不能把率當月合併件數。** 本章以建立日期選樣，再看後續結果；它不是第三季實際發生的所有合併事件，未納入更早建立、第三季才合併的 PR。

14 天內合併率使用相同觀察長度。每筆 PR 至少已存在約 28 天，因此都能完整觀察前 14 天；這仍無法消除內容與作者差異。最終合併率則可能隨未結案件改變。

## 對你的投入決定有什麼意義？

第一次貢獻可以獲得合併，但應把目標放在可重現、範圍小、能清楚驗證的問題。先前成功紀錄可能幫助審查者建立信任，官方規範也明確重視這點。

如果你要做新功能，下一步先看[是否需要開追蹤單](ticket-requirements.md)：公開要求是 GitHub 提案與維護者同意，目前未查到外部貢獻者必須開 Jira。
