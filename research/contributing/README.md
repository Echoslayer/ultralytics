# Ultralytics 開源貢獻研究書

本書幫助準備第一次貢獻 Ultralytics 的讀者選題、查證問題，再提出小範圍修正。先讀[書籍導讀](docs/index.md)，或依下方步驟建置成網頁閱讀。

這是個人研究書。內容保存在 `research/contribution-book` 分支，不用這個分支提出 PR（請官方專案審查並合併修改的請求）。

## 書籍編寫標準：ISO 24495-1:2023

**本書以 ISO 24495-1:2023 淺白語言原則作為編寫與修訂標準。** 適用範圍包括本 README、導讀、正文、表格及操作說明。讀者應能找到需要的資訊、理解內容，並據此採取下一步。[ISO 標準介紹](https://www.iso.org/standard/78907.html)

本書將四項原則落實如下：

| 原則   | 本書的寫法                                     | 修訂時要問的問題                     |
| ------ | ---------------------------------------------- | ------------------------------------ |
| 相關   | 以第一次貢獻所需的規則、證據與步驟為主         | 這段能幫讀者選題、查證或提交修正嗎？ |
| 找得到 | 先寫結論；標題說明內容；並列資訊用表格或清單   | 讀者能快速找到答案嗎？               |
| 看得懂 | 用常見中文、短句和明確主詞；首次使用術語時解釋 | 讀者能讀一遍就說出重點嗎？           |
| 用得上 | 寫清楚操作步驟、繼續條件與停止條件             | 讀者知道接下來要做什麼嗎？           |

本書採用標準公開說明的原則，並以 `iso-24495` 技能的繁體中文寫作方法實作。這是本書的編寫要求，不代表取得 ISO 認證，也不宣稱已完成標準全文的符合性審查。技能中的句長等數字是編輯提醒，不是 ISO 強制條文。

改寫時保留事實、數字、日期、來源與限制。程式識別字、命令和檔案路徑保留原文，方便讀者搜尋與執行。

## 建置成書並開啟預覽

需要先安裝 uv（管理 Python 出版環境的工具）。請在 `research/contributing/` 資料夾開啟 PowerShell，依序執行：

```powershell
$env:UV_CACHE_DIR = Join-Path $PWD '.uv-cache'
uv run --locked mkdocs-run.py build --strict
uv run --locked mkdocs-run.py serve --dev-addr 127.0.0.1:8008
```

建置完成後，開啟 `http://127.0.0.1:8008/`。要停止預覽，回到 PowerShell 按 Ctrl+C。

第一次執行會下載出版套件，不會安裝 Ultralytics 或模型訓練套件。出版工具沿用 `D:\vlm-jev` 的 MkDocs Material（將 Markdown 文件製成網站的工具與主題），以及 uv 指令檔和版本鎖檔 `mkdocs-run.py.lock`。這些設定獨立於模型環境，不修改根目錄的 `pyproject.toml`。

## 直接閱讀或分享建置結果

- 直接開啟 `book/index.html`，可閱讀已建置的書。
- 需要完整搜尋時，請使用上方的本機預覽網址。
- 分享靜態書時，複製整個 `book/` 資料夾，保留檔案結構。

正文放在 `docs/`。建置結果與快取不納入 Git。中文介面與搜尋沿用 Material 的支援，並用 jieba 將中文拆成可搜尋的詞。設定中的 `lang: [en]` 不表示正文只能用英文。

## 修改後先檢查，再正式貢獻

1. 依上方四項原則改寫，保留來源網址與查核日期。
2. 清楚區分來源事實、本書判斷與尚待執行的驗證。
3. 如果新增頁面，同步更新 `mkdocs.yml` 的 `nav` 導覽清單。
4. 重新執行嚴格建置，檢查內部連結和搜尋索引。

這本書沒有模型執行程式。書能成功建置，不表示案例中的問題已在本機重現。

研究資料獨立放在 `research/contributing/`，不加入官方 `docs/en/` 的導覽與發布流程。正式貢獻時，請從更新過的官方專案建立乾淨分支與工作樹（Git 的獨立工作目錄），只帶入該題需要的修正。不要從研究分支直接開 PR。
