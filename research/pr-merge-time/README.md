# Ultralytics：PR 提出後，多久會合併？

研究最近十二個完整月份（2025-10 至 2026-09）建立的 **2,832 筆 PR**，截至 2026-10-29，已有 **2,176 筆合併**。成功合併者的整體中位數為 **5.47 小時**；外部作者為 **16.09 小時**，但外部作者只有 **61.1%** 的投稿已合併。這兩個數字應一起看。

對外部投稿，較實用的描述是：成功合併的 PR 中，50% 在 16.09 小時內、75% 在 1.87 天內、90% 在 11.28 天內完成。這不是新 PR 的保證等待時間。

資料來自 [Ultralytics 官方 PR API](https://api.github.com/repos/ultralytics/ultralytics/pulls?state=all&sort=created&direction=desc&per_page=100)。本頁數字由本機 `data/snapshot.json` 重算；逐筆來源網址保留於 `data/prs.csv` 的 `html_url` 欄位。

## 外部作者：多少 PR 能在期限內合併？

左邊比例只看成功者，右邊以全部外部投稿為分母。後者將關閉未合併與仍開啟的 PR 留在分母，更接近「提出一筆 PR 後，期限內得到合併」的觀察結果。

| 建立後期限 | 期限內合併數 | 占已合併 PR |   占全部外部 PR |
| ---------- | -----------: | ----------: | --------------: |
| 1 小時     |           37 |        6.2% |   37/972 = 3.8% |
| 24 小時    |          380 |       64.0% | 380/972 = 39.1% |
| 3 天       |          487 |       82.0% | 487/972 = 50.1% |
| 7 天       |          526 |       88.6% | 526/972 = 54.1% |
| 30 天      |          554 |       93.3% | 545/956 = 57.0% |

30 天列的右欄，分子與分母皆只納入查核開始前已滿 30 天的 PR，因此是 545/956；左側 554 筆則包含較近期已提早合併的 PR。其他期限的全部投稿皆已觀察足夠久。

外部投稿共 972 筆、324 位作者；368 筆已關閉未合併，10 筆仍開啟。關閉未合併可能是撤回、重複或被其他方案取代，不能一律視為被拒絕。

## 少數高產作者是否主導結果？

- 每位外部作者只取研究期間最早一筆 PR：324 筆中 142 筆已合併（43.8%）；成功者中位數 35.90 小時、P90 99.12 天。
- 排除已合併 PR 數最多的一位外部作者：862 筆中 486 筆已合併（56.4%）；成功者中位數 15.93 小時、P90 20.19 天。

「期間最早一筆」不代表作者生涯第一筆，也不等於新手。以上只是敏感度比較，沒有控制修改規模、內容、品質或事前協調。

## 範圍、方法與限制

- 與研究書的關係：研究書第五、九章只用 2026 年第三季的 1,247 筆 PR，並依作者在季度開始前的紀錄判定外部作者；本頁用十二個月、依查核時帳號關係分組。第三季外部已合併 PR 的中位數是 14.13 小時，與本頁 16.09 小時的期間與分組都不同，不能直接相減。

- 研究對象：`ultralytics/ultralytics` 官方 repo，所有目標分支；建立時間範圍為 `2025-10-01T00:00:00Z`（含）至 `2026-10-01T00:00:00Z`（不含）。不是專案全歷史普查。
- 擷取期間：`2026-10-29T05:29:42.604166+00:00` 至 `2026-10-29T05:31:57.318119+00:00`。REST API `state=all`、`sort=created`、`direction=desc`、每頁 100 筆；共 33 頁，最後一頁最舊建立時間 `2025-09-19T05:07:01Z`，已跨過研究起點。排除研究期間外的資料後分析。
- 分頁存檔包含每頁擷取的必要 metadata，不含完整 PR 內文。不是 Search API 的前 1,000 筆結果。API 是逐頁讀取，不是原子快照；期間新增或變更仍可能造成漂移。以 PR 編號去重，並保留頁面資料供核對。
- 維護者群組依查核時 `MEMBER`／`OWNER`／`COLLABORATOR` 分類；自動化為 GitHub `Bot` 或 `UltralyticsAssistant`；`ghost` 另列，其餘列外部。這不是僱用身分或投稿當時的歷史身分，也沒有判斷內容是否由 AI 撰寫。
- 中位數與百分位只計入已合併 PR；未合併不填成零或無限大，也未使用存活分析推估其未來。每筆 PR 等權，百分位採排序後線性插值。
- 草稿歷程、首次回覆、首次 approval 與 CI 等待時間不在此次資料內，無法拆解各階段耗時或建立因果關係。
- 驗證項目：研究時間邊界、PR 編號唯一、合併不早於建立、合併者狀態為 closed、各群組及狀態加總一致。

API 規格：[GitHub List pull requests](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests)。關係欄位：[CommentAuthorAssociation](https://docs.github.com/en/graphql/reference/enums#commentauthorassociation)。

## 本機檔案與重算

- `data/page-*.json`：逐頁擷取 metadata。
- `data/snapshot.json`：研究 cohort 與擷取時間。
- `data/prs.csv`：可用 Excel 開啟的逐筆資料，含群組、耗時與來源連結。
- `data/summary.json`：分組、月份、分位數與敏感度摘要。
- `data/analyze.py`、`data/report.py`：本機擷取、分析與產生報告腳本。

在工作樹根目錄執行：

```powershell
.venv-local-test/Scripts/python.exe research/pr-merge-time/data/analyze.py
.venv-local-test/Scripts/python.exe research/pr-merge-time/data/report.py
```

重新抓取可在第一個命令加 `--fetch`，會覆寫本輪資料。`data/` 已由根目錄 `.gitignore` 排除，沒有 commit 或 push；本報告可獨立閱讀，但離線重算需要保留本機 data 目錄。
